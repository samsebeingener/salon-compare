# Правила агента

Проект: сравнение трех маникюрных салонов Москвы для инвестора.

## Обязательные ограничения
- Язык: Python 3.12+.
- Веб-интерфейс: Streamlit.
- База: SQLite, один файл рядом с проектом.
- Никаких микросервисов, очередей, авторизации, личных кабинетов.
- Один процесс, один файл базы.
- Ответы модели обязательно валидируются через Pydantic.
- Тесты не ходят в интернет.
- Все внешние ответы модели и источников в тестах заменяются фикстурами.
- Ключи только через переменные окружения.
- .env не коммитится.
- Каждое значение в отчете должно иметь источник или пометку «не найдено» / «не подтверждено».
- Если данных нет, нельзя маскировать это нулем или средним.
- Любая фича или исправление поведения — только через цикл OpenSpec (см. раздел ниже): change → тесты → код → PR → архив.
- Не добавлять новые зависимости без моего разрешения.
- Не усложнять архитектуру без моего разрешения.

## Стиль работы
- Одна задача — одна ветка — один pull request.
- Коммиты мелкие и понятные.
- Сначала тест, потом реализация.
- После каждой задачи запускаются линтер, типы и тесты.

## OpenSpec (обязательный цикл)

**Что где лежит:**
- `openspec/specs/` — актуальная правда: что продукт делает **сейчас**.
- `openspec/changes/<имя>/` — активное предложение (как открытая ветка): proposal, design, tasks, дельты спеков.
- `openspec/changes/archive/` — закрытые изменения (история).

**Цикл для любой фичи или фикса** (кроме мелких опечаток без смены поведения):

1. Создать папку change: proposal → design → tasks → spec deltas.
2. Красные тесты → реализация → quality gate (линтер, типы, тесты).
3. PR в `main`.
4. **После merge PR:** заархивировать change (`openspec archive <имя>` или ручная синхронизация по `.cursor/skills/openspec-sync-specs/SKILL.md`) — перенести в `archive/`, влить дельты в `openspec/specs/`.
5. В `openspec/changes/` не копить готовое: одновременно **0–1** активный change.

**Запрещено:** мержить код, который противоречит живым `openspec/specs/`, без обновления спеков в том же PR или сразу следом archive-PR.

**Исключение:** правки опечаток и чисто документационные правки без изменения поведения.

Конфиг и скиллы: `openspec/config.yaml`, `.cursor/skills/openspec-*` (propose, apply, archive, sync-specs и др.).
