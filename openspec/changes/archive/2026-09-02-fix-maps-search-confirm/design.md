# Design: fix-maps-search-confirm

## Context

`PassthroughResolver` и `fetch_card` с условием «ровно один хит» ломали правило неоднозначности.

## Goals / Non-Goals

**Goals:** поиск на резолвере, подтверждение по ссылкам, ключи в Compose, fetch по id.

**Non-Goals:** ЕГРЮЛ, индекс, LLM-парсер HTML, соседи 500 м в живом API.

## Decisions

- `PlaceCatalog.search` всегда возвращает список (0..n). Резолвер не берёт «первую».
- Ссылка на карту → одна карточка из URL, без поиска.
- Сайт: поиск по домену; если пусто — кандидат-сайт, чтобы GET страницы был возможен.
- Название / ОГРН / ИНН / текст: только поиск карт. 0 или 2+ → уточнение.
- `apply_slot_choices` после radio в Streamlit.
- Compose: явные `environment` для ключей.

## Risks / Trade-offs

- Две карточки одной студии в 2ГИС и Яндекс покажут два пункта — пользователь выбирает, это лучше молчаливого пропуска.
