## Purpose

Приём трёх зацепок на запуск: распознать тип, не угадывать точку при нескольких кандидатах, не сравнивать объект с самим собой.

## ADDED Requirements

### Requirement: Три непустые зацепки на запуск
Система SHALL принимать запуск только если пользователь передал ровно три непустые зацепки. Пустая строка MUST не считаться зацепкой. Меньше или больше трёх непустых MUST останавливать разбор с понятным сообщением, без угадывания недостающих точек.

#### Scenario: Ровно три зацепки
- GIVEN три непустые строки (сайт, название, ОГРН)
- WHEN запускают разбор зацепок
- THEN все три принимаются к классификации
- THEN разбор не требует четвёртую зацепку

#### Scenario: Не три зацепки
- GIVEN две непустые строки и одна пустая
- WHEN запускают разбор зацепок
- THEN статус не «готово к сбору»
- THEN пользователь видит, что нужны три зацепки

### Requirement: Распознавание типа зацепки без модели
Система SHALL классифицировать каждую зацепку по содержимому, без вызова LLM. Поддерживаемые типы MUST включать: сайт, название, ОГРН, ИНН, ссылка на карты, ссылка на онлайн-запись, свободный текст.

#### Scenario: Демо-тройка из подготовки
- GIVEN `https://pinklemon-nails.ru/baumanskaya`, `Вишня Таганская` и `1147746349552`
- WHEN классифицируют зацепки
- THEN первая имеет тип сайта
- THEN вторая имеет тип названия
- THEN третья имеет тип ОГРН

#### Scenario: ИНН, карта и обрывок текста
- GIVEN десятизначный ИНН, ссылка на Яндекс Карты или 2ГИС и длинная свободная фраза
- WHEN классифицируют зацепки
- THEN типы соответственно ИНН, ссылка на карты и свободный текст

### Requirement: Неоднозначность — список со ссылками, без выбора за пользователя
Если резолвер для одной зацепки вернул не ровно одного кандидата, система MUST NOT выбирать точку сама. Система SHALL показать список кандидатов со ссылками на источники и попросить подтвердить, какую точку разбирать. Ноль кандидатов SHALL также считаться неоднозначностью: просим уточнить зацепку.

#### Scenario: Несколько похожих салонов
- GIVEN зацепка-название, по которой резолвер вернул двух кандидатов со ссылками
- WHEN запускают разбор зацепок
- THEN статус «нужно уточнение»
- THEN в ответе есть оба кандидата и их ссылки
- THEN нет выбранной точки «по умолчанию»

#### Scenario: Ни одного кандидата
- GIVEN зацепка, по которой резолвер вернул пустой список
- WHEN запускают разбор зацепок
- THEN статус «нужно уточнение»
- THEN систему не считает точку найденной

### Requirement: Две зацепки — одна точка
Если две принятые зацепки резолвер связал с одним и тем же идентификатором точки, система MUST NOT сравнивать объект с самим собой. Система SHALL сообщить, что это одна точка, показать ссылки и попросить заменить одну из трёх зацепок.

#### Scenario: Сайт и ОГРН одной студии
- GIVEN три зацепки, из которых две резолвер сводит к одному id точки
- WHEN запускают разбор зацепок
- THEN статус «дублирующиеся точки»
- THEN в ответе есть ссылки на совпавшую точку
- THEN нет статуса «готово к сбору» для этой тройки

### Requirement: Готовность без сбора данных
Когда три зацепки однозначно указывают на три разные точки, система SHALL пометить запуск готовым к сбору. Это изменение MUST NOT запрашивать API карт, HTML карточек, ЕГРЮЛ и MUST NOT строить сравнительный отчёт.

#### Scenario: Три разные точки
- GIVEN три зацепки, каждая с ровно одним кандидатом, и три разных id
- WHEN запускают разбор зацепок
- THEN статус «готово к сбору»
- THEN отчёта по салонам нет
