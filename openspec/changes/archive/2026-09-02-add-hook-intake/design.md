# Design: add-hook-intake

## Context

Нужен разбор зацепок до любых HTTP-запросов. Поиск точек на картах будет в следующем изменении; здесь достаточно порта резолвера, который в тестах подменяется, а в приложении не ходит в сеть.

## Goals / Non-Goals

**Goals:**

- Классификация строки → тип зацепки правилами, без LLM.
- Оркестрация трёх слотов: счёт, неоднозначность, дубли id.
- Три поля в Streamlit, показ статуса и ссылок.

**Non-Goals:**

- Запросы 2ГИС / Яндекс / HTML / ЕГРЮЛ.
- Сравнительная таблица, индекс, SQLite.
- Новые pip-зависимости.

## Decisions

- Слои без новых пакетов: `hooks.py` (тип), `intake.py` (статус + протокол резолвера), `app.py` (поля).
- В приложении резолвер-заглушка: одна точка на зацепку с id из нормализованной строки. Неоднозначность и «две зацепки — один салон» проверяются тестами с подставным резолвером; живой поиск — следующий PR.
- ОГРН: 13 или 15 цифр. ИНН: 10 или 12 цифр. Ссылки карт: хост Яндекса с `/maps` или `2gis`. Запись: `yclients` / `dikidi`. Иначе URL → сайт. Короткая фраза без URL → название. Остальное непустое → свободный текст.

## Risks / Trade-offs

- Заглушка резолвера не покажет в UI живую неоднозначность «Вишня Таганская» до PR сбора. Это сознательно: иначе пришлось бы ходить в сеть или хардкодить фейковые салоны.
- Эвристика названия vs свободный текст может ошибаться на коротких обрывках — тогда тип «свободный текст», разбор всё равно идёт дальше или ждёт резолвер.
