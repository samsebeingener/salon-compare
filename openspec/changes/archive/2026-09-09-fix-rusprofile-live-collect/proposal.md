# Proposal: fix-rusprofile-live-collect

## Why

Живой прогон после #8: DuckDuckGo GET рвёт TCP (WinError 10054), POST HTML-поиска отдаёт карточку `/id/7301223`. Страница rusprofile 200 с ОГРН и «Действующая организация», но классификатор видит `"has_captcha":true` в JSON платного виджета и режет тело. Парсер статуса принимает «ликвидированных связанных организаций» за ликвидацию самой фирмы; ОКВЭД берётся из меню, не из «Основной вид деятельности».

## What Changes

- Поиск DuckDuckGo HTML — POST формы, не GET.
- `"has_captcha"` / `"disable_captcha"` в JSON не равны капче страницы. Настоящая капча/403 по-прежнему закрыто. Капчу не решаем.
- Статус юрлица: сначала карточка («действующая организация» / «ликвидированная организация»), не чужие связанные.
- Вид деятельности — с маркера «основной вид деятельности», не первое «оквэд» в меню.
