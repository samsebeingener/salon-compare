# Proposal: add-scoring-formula

## Why

Таблица полей есть, индекса привлекательности нет. Задание и подготовка: 40/25/20/15, нет данных ≠ ноль, две карты не усреднять, устойчивость только если открылись Федресурс и КАД.

## What Changes

- Считать четыре блока по фикстурам полей. Итог примерно 0–100 только из блоков, которые удалось посчитать. Пропущенный блок не пишет 0.
- Репутация 40%: в баллы один источник. Две карты без даты свежести — «не ясно какой свежее», блок не считаем. +3 не ставим без свежих отзывов. Негатив 0 не ставим без плюс/минус.
- Устойчивость 25%: только если Федресурс и КАД с полкой found. Возраст по дате ЕГРЮЛ. Нет сигнала судов — без +1 и без −2.
- Локация 20% и масштаб 15%: пока нет типа точки и числа мастеров — блоки не считаем, соседей в вес не кладём.
- В таблице строка индекса и пояснение. Нет «покупай». Вывода модели нет.
- Старые SQLite без поля score читаются. Новых зависимостей нет.

## Capabilities

### New Capabilities

- `scoring-formula`: расчёт блоков и частичного индекса.

### Modified Capabilities

- `hook-intake`: после сбора индекс считается (дыры честные).
- `project-bootstrap`: таблица может показать индекс; совет «покупай» запрещён.
- `open-data-collect`: запись точки несёт счёт.
- `saved-runs`: сохранённый разбор показывает индекс по сохранённым полям.

## Impact

- Код: `score.py`, поля `PlaceRecord`, Streamlit, README, тесты без сети.
- Не входит: карточки салона, вывод LLM, правка недостоверности, HTML-парсер отзывов за 90 дней.
