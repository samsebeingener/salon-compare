## MODIFIED Requirements

### Requirement: Распознавание типа зацепки без модели
Система SHALL классифицировать каждую зацепку по содержимому, без вызова LLM. Поддерживаемые типы MUST включать: сайт, название, ОГРН, ИНН, ссылка на карты, ссылка на онлайн-запись, свободный текст. URL `yandex.ru/maps` MUST оставаться типом «ссылка на карты». Система MUST NOT вызывать API Яндекса, чтобы загрузить эту карточку.

#### Scenario: Демо-тройка из подготовки
- GIVEN `https://pinklemon-nails.ru/baumanskaya`, `Вишня Таганская` и `1147746349552`
- WHEN классифицируют зацепки
- THEN первая имеет тип сайта
- THEN вторая имеет тип названия
- THEN третья имеет тип ОГРН

#### Scenario: ИНН, карта и обрывок текста
- GIVEN десятизначный ИНН, ссылка на Яндекс Карты или 2ГИС и длинная свободная фраза
- WHEN классифицируют зацепки
- THEN типы соответственно ИНН, ссылка на карты и свободный текст

### Requirement: Неоднозначность — список со ссылками, без выбора за пользователя
Живой резолвер SHALL искать точки в API 2ГИС по типу зацепки. Система MUST NOT искать в каталоге Яндекса. Если по зацепке не ровно одна карточка и поиск вернул несколько хитов, система MUST NOT выбирать точку, MUST NOT помечать поля «не найдено» из‑за нескольких хитов и MUST NOT подставлять fallback. Система SHALL показать все найденные карточки со ссылками и дождаться подтверждения пользователя. Сбор полей MUST NOT начинаться, пока каждая зацепка не сведена к одной точке. Интерфейс MUST NOT подставлять первую карточку списка, если пользователь ничего не выбрал. Если поиск вернул ноль карточек, система SHALL дать одну синтетическую точку для сайта, ссылки записи, ОГРН, ИНН, названия и свободного текста (id по типу зацепки). Ссылка на карты MUST резолвиться из URL, без каталога.

#### Scenario: Несколько похожих салонов
- GIVEN зацепка-название, по которой поиск 2ГИС вернул две карточки со ссылками
- WHEN запускают разбор зацепок
- THEN статус «нужно уточнение»
- THEN в ответе есть оба кандидата и их ссылки
- THEN нет выбранной точки «по умолчанию»
- THEN таблица полей ещё не строится
- THEN синтетический fallback для названия не создаётся

#### Scenario: Пользователь подтвердил карточку из списка
- GIVEN статус уточнения и две карточки по одной зацепке
- WHEN пользователь указывает id одной карточки
- THEN эта зацепка считается однозначной
- THEN если остальные слоты однозначны и id различны — статус «готово к сбору»

#### Scenario: Ни одного кандидата
- GIVEN зацепка сайта, ОГРН или названия, по которой поиск 2ГИС вернул пустой список
- WHEN запускают разбор зацепок
- THEN система даёт одну синтетическую точку по типу зацепки
- THEN слот считается однозначным без «нужно уточнение» из‑за пустого каталога

#### Scenario: Пустой radio не берёт первую карточку
- GIVEN две карточки в списке и нет выбранного id
- WHEN подтверждают точки
- THEN статус остаётся «нужно уточнение»
- THEN первая карточка не считается выбранной

#### Scenario: Демо-тройка без карточек карт
- GIVEN `https://pinklemon-nails.ru/baumanskaya`, `Вишня Таганская` и `1147746349552`, и каталог 2ГИС пустой
- WHEN запускают разбор зацепок
- THEN статус «готово к сбору»
- THEN три разных id: сайт, название, ОГРН
- THEN первую карточку карт система не выбирала — карточек не было
