## ADDED Requirements

### Requirement: Гибридный LLM-добор только MISSING
После детерминированного сбора (`collect_place` / `collect_three`) система MAY добрать поля whitelist моделью. Парсеры MUST оставаться источником истины для FOUND. Добор MUST трогать только поля со статусом «не найдено» (trust MISSING или пустой value) из whitelist: `site_about` и `egrul_activity`; часы (`hours`) MAY входить в тот же патч. На одну точку SHALL быть не больше одного вызова модели, если есть хотя бы одна дыра. Ответ MUST разбираться схемой Pydantic (`ExtractPatch`). Успешно добранное поле MUST иметь полку «слабо» и `source_url` ровно `модель`. Невалидный JSON, пустой патч или пустая строка MUST оставить поле «не найдено». Отсутствие ключа модели MUST пропустить добор без падения. Модуль добора MUST NOT сам делать HTTP. Вызов SHALL идти из приложения после `collect_three` на свежем сборе, MUST NOT жить в клиенте карт (`maps_http`) и MUST NOT подменять каскад внутри `collect_place`. Точка со сбоем сбора (`collect_ok` ложь) MUST NOT отправляться в добор. Повторная отрисовка с кэшем тех же точек MUST NOT вызывать добор снова.

#### Scenario: Дыра заполняется слабо из JSON модели
- GIVEN после парсеров `site_about` — «не найдено», ключ модели есть, фикстура LLM вернула JSON `{"site_about":"Студия с 2014"}`
- WHEN делают добор точки
- THEN `site_about` заполнен текстом из JSON
- THEN полка слабо
- THEN `source_url` равен `модель`
- THEN вызов модели один

#### Scenario: FOUND не перезаписывается
- GIVEN парсер уже заполнил `egrul_activity` как FOUND
- AND модель вернула другой текст деятельности
- WHEN применяют патч
- THEN значение и источник парсера не меняются

#### Scenario: Невалидный JSON
- GIVEN дыра в `site_about` и ответ модели не JSON
- WHEN делают добор
- THEN `site_about` остаётся «не найдено»

#### Scenario: Нет ключа модели
- GIVEN клиент модели пустой (`NullLlm`) и поля whitelist пустые
- WHEN заканчивают свежий сбор трёх точек
- THEN добор не вызывается
- THEN поля остаются «не найдено»
- THEN приложение не падает

#### Scenario: Нет дыр — модель молчит
- GIVEN whitelist уже FOUND
- WHEN вызывают добор
- THEN `complete` не вызывается

#### Scenario: Не из клиента карт
- GIVEN исходники сбора карт
- WHEN проверяют, где вызывается добор
- THEN модуля `maps_http` в цепочке добора нет
- THEN вызов после `collect_three` в приложении
