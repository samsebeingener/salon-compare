## MODIFIED Requirements

### Requirement: Неоднозначность — список со ссылками, без выбора за пользователя
Живой резолвер SHALL искать точки в API карт по типу зацепки. Если поиск вернул несколько карточек, система MUST NOT выбирать точку и MUST NOT подставлять fallback. Система SHALL показать все найденные карточки со ссылками и дождаться подтверждения. Сбор полей MUST NOT начинаться, пока каждая зацепка не сведена к одной точке. Если поиск вернул ноль карточек, система SHALL дать одну синтетическую точку для сайта, ссылки записи, ОГРН, ИНН, названия и свободного текста (id по типу зацепки). Ссылка на карты без разобранного id MUST остаться без точки: статус уточнения, не «готово к сбору».

#### Scenario: Несколько похожих салонов
- GIVEN зацепка-название, по которой поиск карт вернул две карточки со ссылками
- WHEN запускают разбор зацепок
- THEN статус «нужно уточнение»
- THEN в ответе есть оба кандидата и их ссылки
- THEN нет выбранной точки «по умолчанию»
- THEN таблица полей ещё не строится
- THEN синтетический fallback для названия не создаётся

#### Scenario: Пользователь подтвердил карточку из списка
- GIVEN статус уточнения и две карточки по одной зацепке
- WHEN пользователь указывает id одной карточки
- THEN эта зацепка считается однозначной
- THEN если остальные слоты однозначны и id различны — статус «готово к сбору»

#### Scenario: Демо-тройка без карточек карт
- GIVEN `https://pinklemon-nails.ru/baumanskaya`, `Вишня Таганская` и `1147746349552`, и оба каталога карт пустые
- WHEN запускают разбор зацепок
- THEN статус «готово к сбору»
- THEN три разных id: сайт, название, ОГРН
- THEN первую карточку карт система не выбирала — карточек не было

#### Scenario: Ссылка на карты без id
- GIVEN зацепка-ссылка на карты, которую резолвер не разобрал в карточку, и пустой поиск
- WHEN запускают разбор зацепок
- THEN у этого слота нет кандидатов
- THEN статус не «готово к сбору»
