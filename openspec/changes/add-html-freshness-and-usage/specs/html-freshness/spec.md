## ADDED Requirements

### Requirement: Часы, свежесть отзывов и плюс/минус из открытого HTML
Если API не отдал часы, дату последнего отзыва или разбивку плюс/минус, система SHALL взять их из одного GET открытой HTML-страницы той же карточки. Разбор MUST быть схемой Pydantic, без новых зависимостей. Капча MUST дать «не найдено». Система MUST NOT подставлять ноль, средний рейтинг или выдуманный плюс/минус. Дата последнего отзыва и признак отзывов за 90 дней SHALL попасть в отчёт.

#### Scenario: HTML с датой отзыва, часами и плюс/минус
- GIVEN открытый HTML с JSON-LD отзывом от 15.08.2026, графиком «пн-вс 10:00–21:00», «положительных 40» и «отрицательных 3»
- WHEN разбирают страницу
- THEN есть дата последнего отзыва
- THEN есть часы
- THEN плюс/минус заполнены из этих цифр

#### Scenario: HTML без разбивки
- GIVEN HTML с рейтингом, без слов «положительных» / «отрицательных»
- WHEN разбирают страницу
- THEN плюс/минус — не найдено, не ноль

### Requirement: Расход токенов запуска
После вызова модели система SHALL показать число токенов из ответа API, если оно пришло. Оценка денег MUST считаться только при заданных тарифах `LLM_USD_PER_1M_PROMPT` и `LLM_USD_PER_1M_COMPLETION`. Иначе стоимость MUST быть «не найдена». Отсутствие ключа модели MUST оставить расход пустым, без падения. Старый SQLite без блока usage MUST открываться.

#### Scenario: Ответ с usage, тарифа нет
- GIVEN `usage.prompt_tokens=100` и `completion_tokens=50`, тарифы пустые
- WHEN считают расход
- THEN токены 150
- THEN стоимость не найдена

#### Scenario: Есть тариф
- GIVEN те же токены и тарифы 1 и 2 доллара за миллион
- WHEN считают расход
- THEN стоимость считается линейно, без выдуманного прайса модели
