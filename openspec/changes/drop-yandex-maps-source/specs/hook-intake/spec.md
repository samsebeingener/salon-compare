## MODIFIED Requirements

### Requirement: Распознавание типа зацепки без модели
Система SHALL классифицировать каждую зацепку по содержимому, без вызова LLM. Поддерживаемые типы MUST включать: сайт, название, ОГРН, ИНН, ссылка на карты, ссылка на онлайн-запись, свободный текст. URL `yandex.ru/maps` MUST оставаться типом «ссылка на карты». Система MUST NOT вызывать API Яндекса, чтобы загрузить эту карточку.

#### Scenario: Демо-тройка из подготовки
- GIVEN `https://pinklemon-nails.ru/baumanskaya`, `Вишня Таганская` и `1147746349552`
- WHEN классифицируют зацепки
- THEN первая имеет тип сайта
- THEN вторая имеет тип названия
- THEN третья имеет тип ОГРН

#### Scenario: ИНН, карта и обрывок текста
- GIVEN десятизначный ИНН, ссылка на Яндекс Карты или 2ГИС и длинная свободная фраза
- WHEN классифицируют зацепки
- THEN типы соответственно ИНН, ссылка на карты и свободный текст

### Requirement: Неоднозначность — список со ссылками, без выбора за пользователя
Живой резолвер SHALL искать точки в API 2ГИС по типу зацепки. Система MUST NOT искать в каталоге Яндекса. Если по зацепке не ровно одна карточка, система MUST NOT выбирать точку и MUST NOT помечать поля «не найдено» из‑за нескольких хитов. Система SHALL показать все найденные карточки со ссылками и дождаться подтверждения пользователя. Сбор полей MUST NOT начинаться, пока каждая зацепка не сведена к одной точке.

#### Scenario: Несколько похожих салонов
- GIVEN поиск 2ГИС вернул две карточки с разными ссылками
- WHEN ещё нет выбора пользователя
- THEN статус не «готово к сбору»
- THEN в ответе есть ссылки обеих карточек
