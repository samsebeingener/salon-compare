# Proposal: improve-streamlit-report-ux

## Why

Приёмка показала, что отчёт в Streamlit плохо читается: карточки точки (`card_payload` / `CardView`) не выводятся, карта смешана с таблицей, нет лидеров по блокам индекса, прогресс сбора — один spinner на все точки. Нужно привести UI к блокам ревью, не меняя формулу и каскад сбора.

## What Changes

- На каждую точку — expander с существующим `card_payload` / `CardView`: поля, источники, missing.
- Отчёт разделён на блоки: карта (справочно) / сравнение / карточки / вывод модели / расход.
- Таблица сравнения: zebra, `tabular-nums`, лидеры по `PlaceScore.blocks` (репутация / устойчивость / локация) и по индексу.
- Прогресс сбора: `st.status` вида «точка i из n · этап» вместо голого spinner «Собираем поля по трём точкам».
- Контейнер отчёта с `max-width` около 1100px.
- Правка ячеек по-прежнему сохраняется (сессия + SQLite).

## Capabilities

### New Capabilities

- (нет)

### Modified Capabilities

- `streamlit-ui`: раскладка отчёта, карточки в expander, таблица с лидерами и zebra/`tabular-nums`, `st.status` сбора, ширина контейнера; правки ячеек не ломаются.

## Impact

- Код (другой агент): в основном `app.py` (рендер отчёта, CSS, статус сбора). `card_payload` / `CardView` / `PlaceScore.blocks` уже есть — не дублировать схему карточки.
- Тесты: `test_hook_intake.py` сейчас требует строку «Собираем поля по трём точкам» — заменить на контракт `st.status` / «точка i из n».
- Не входит: scoring, каскад collect, карта Яндекс как источник данных, `report.py` CardView-контракт (только показ).

## Non-Goals

- Менять `card_payload`, `FIELD_LABELS`, формулу 50/25/25 или payload SQLite.
- Новый capability для карточек (`report-corrections` уже описывает данные карточки; этот change — только UI).
- Менять ключи Яндекса / XSS-контракт карты.
- Композерский редизайн всего intake (зацепки, disambiguation).
