# Design: add-legal-registries

## Context

Intake уже сводит зацепки к трём точкам. Сбор карт есть. Реестры — открытый HTML, без ключей API. Pytest не ходит в сеть.

## Goals / Non-Goals

**Goals:** ОГРН/ИНН, ЕГРЮЛ + Федресурс + КАД, подтверждение при нескольких юрлицах, честные дырки, таблица.

**Non-Goals:** баллы 25%, список учредителей, обход капчи, живые запросы в CI.

## Decisions

- `LegalOrg(ogrn, title, source_url)`. Резолв: зацепка ОГРН → ровно одна запись; ИНН → поиск (0..n); иначе уникальные ОГРН/ИНН с двух карт.
- 0 идентификаторов → юрполя `trust=missing`, `value=None`. Не подставлять «нет» / «чисто».
- 2+ записи → `legal_candidates` со ссылками, юрполя не помечаются как «не найдено» из‑за числа хитов; UI просит подтвердить. После выбора — сбор по этому ОГРН.
- По реестру: один GET URL с ОГРН/ИНН. `ok` + разбор Pydantic → поле со ссылкой. `blocked`/`empty` → только этот реестр «не найдено».
- Явный пустой результат парсера («не обнаружено») — это найдено, не дырка. Отсутствие маркера в HTML — дырка, не «долгов нет».
- Учредители в схеме не существуют.
- Живой разбор — консервативные маркеры в HTML; в тестах парсер и поиск подставляются.

## Risks / Trade-offs

- Федресурс и КАД часто JS/капча — тогда честно «не найдено», устойчивость позже не считаем.
- Два разных ОГРН с Яндекса и 2ГИС — спрашиваем, даже если «очевидно».
