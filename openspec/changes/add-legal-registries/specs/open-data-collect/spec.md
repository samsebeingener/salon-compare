## Purpose

Сбор открытых полей трёх точек: каскад API карт, затем один HTML, иначе «не найдено». Точки независимы. Капчу не обходим. Юрполя — отдельным каскадом реестров.

## ADDED Requirements

### Requirement: Юрполя из открытых реестров
Если у точки есть ровно один идентификатор юрлица (ОГРН или ИНН), система SHALL собрать: дату регистрации, статус, вид деятельности из ЕГРЮЛ; сигнал Федресурса; сигнал КАД по компании. Каждое значение MUST иметь ссылку источника или пометку «не найдено». Система MUST NOT собирать учредителей и MUST NOT подставлять «долгов нет», если реестр не открылся.

#### Scenario: ОГРН из зацепки, три реестра открылись
- GIVEN зацепка ОГРН `1147746349552` и фикстуры HTML ЕГРЮЛ, Федресурс и КАД без защиты
- WHEN собирают поля точки
- THEN заполнены дата регистрации, статус, вид деятельности, сигнал Федресурса и сигнал КАД
- THEN у каждого юрполя есть ссылка на соответствующий реестр
- THEN в записи нет полей учредителей

#### Scenario: Нет ОГРН и ИНН
- GIVEN зацепка-сайт и карточки карт без ОГРН и ИНН
- WHEN собирают поля точки
- THEN юрполя имеют пометку «не найдено»
- THEN значение не равно «долгов нет», «чисто» или нулю

#### Scenario: Федресурс закрыт, ЕГРЮЛ открыт
- GIVEN один ОГРН, HTML ЕГРЮЛ без защиты, HTML Федресурса с капчей или 403
- WHEN собирают поля точки
- THEN поля ЕГРЮЛ заполнены
- THEN Федресурс — «не найдено»
- THEN защиту не обходят повторными запросами

### Requirement: Несколько юрлиц — подтверждение со ссылками
Если поиск по ИНН или два источника карт дали больше одной записи юрлица, система MUST NOT выбирать первую и MUST NOT помечать юрполя «не найдено» из‑за числа хитов. Система SHALL показать список со ссылками и дождаться подтверждения. После выбора ОГРН SHALL собрать реестры этой записи.

#### Scenario: Два разных ОГРН с карт
- GIVEN карточка Яндекса с одним ОГРН и карточка 2ГИС с другим ОГРН, обе со ссылками
- WHEN собирают поля точки без выбора пользователя
- THEN в ответе есть оба кандидата и их ссылки
- THEN юрполя не заполнены как «не найдено» из‑за двух хитов
- THEN ни один ОГРН не выбран по умолчанию

#### Scenario: ИНН нашёл две организации
- GIVEN зацепка-ИНН и поиск ЕГРЮЛ вернул две организации со ссылками
- WHEN собирают поля без выбора
- THEN статус уточнения юрлица
- THEN в ответе есть обе ссылки
- THEN реестры ещё не разбираются как выбранная компания

#### Scenario: Пользователь подтвердил юрлицо
- GIVEN два кандидата юрлица и фикстуры реестров для выбранного ОГРН
- WHEN пользователь указывает один ОГРН
- THEN юрполя собираются по этой записи
- THEN второй ОГРН не подставляется

## MODIFIED Requirements

### Requirement: Каскад поля API затем HTML затем не найдено
Для каждого сравниваемого поля система SHALL сначала взять значение из JSON API 2ГИС и/или Яндекс. Если поля нет в ответе (пусто, нет ключа, нет ключа API, ошибка запроса), система SHALL сделать не больше одного GET открытой HTML-страницы той же карточки. Если HTML не дал поле — значение MUST быть «не найдено», без нуля и без среднего. Сбор SHALL загружать карточку по идентификатору уже выбранной точки. Несколько результатов поиска на шаге зацепок MUST NOT превращаться в «не найдено» на шаге полей.

#### Scenario: Полный ответ API
- GIVEN фикстура API 2ГИС и Яндекс с рейтингом и числом отзывов
- WHEN собирают поля точки
- THEN оба рейтинга заполнены из API со ссылкой источника
- THEN HTML для этих полей не вызывается

#### Scenario: В API нет рейтинга, HTML отдал
- GIVEN API Яндекса без рейтинга и HTML карточки с рейтингом
- WHEN собирают поля точки
- THEN рейтинг Яндекса берётся из HTML со ссылкой страницы
- THEN поле не заполняется нулём

#### Scenario: API пусто и HTML закрыт
- GIVEN пустой API и HTML с капчей, логином или 403
- WHEN собирают поля точки
- THEN рейтинг и отзывы этой карты имеют пометку «не найдено»
- THEN значение не подменяется нулём или средним
- THEN защиту (капча/логин) не обходят повторными запросами

#### Scenario: Поиск нашёл несколько карточек
- GIVEN поиск по зацепке вернул больше одной карточки
- WHEN ещё нет подтверждения пользователя
- THEN поля не заполняются как «не найдено» из‑за числа хитов
- THEN сначала запрашивается подтверждение со ссылками

### Requirement: Три точки независимо
Сбой или пустые поля одной точки MUST NOT отменять сбор двух других. Система SHALL вернуть запись по каждой из трёх точек.

#### Scenario: Один источник молчит у одной точки
- GIVEN у первой точки API Яндекса пуст, у второй и третьей API полон
- WHEN собирают три точки
- THEN первая точка остаётся в результате с дырками «не найдено» где пусто
- THEN вторая и третья точки собраны
- THEN запуск не останавливается целиком

### Requirement: Соседи в радиусе 500 м
Система SHALL собрать число похожих студий в ~500 м и одну строку: их средний рейтинг выше или ниже нашей точки. Сначала API радиуса; если поля нет — один GET HTML. Иначе «не найдено». Число соседей MUST NOT подменяться нулём, если данных нет.

#### Scenario: Соседи из API
- GIVEN API радиуса вернул число соседей и средний рейтинг выше нашей точки
- WHEN собирают поля точки
- THEN есть число соседей и пометка «выше»
- THEN HTML соседей не вызывается

#### Scenario: Соседей нет в API и HTML закрыт
- GIVEN API радиуса без числа соседей и HTML с 403
- WHEN собирают поля точки
- THEN соседи — «не найдено», не ноль

### Requirement: Сайт студии один GET
Если у точки есть URL сайта, система SHALL сделать один GET открытой страницы. Капча, логин или 403 MUST дать «не найдено» для полей сайта. Успешный GET MAY заполнить краткое «о нас», если разбор HTML (схема Pydantic) это вернул.

#### Scenario: Сайт открылся
- GIVEN URL сайта и HTML без защиты, парсер вернул текст «о нас»
- WHEN собирают поля точки
- THEN поле сайта заполнено со ссылкой на URL
- THEN повторного GET нет

#### Scenario: Сайт закрыт
- GIVEN URL сайта и ответ 403
- WHEN собирают поля точки
- THEN поле сайта — «не найдено»
