# Proposal: add-legal-registries

## Why

Карты уже собираются, но блока устойчивости нет: возраст и статус юрлица, банкротство и суды компании. Без ЕГРЮЛ / Федресурс / КАД нельзя честно оставить устойчивость пустой (сценарий «нет ОГРН») и нельзя позже считать 25%. Несколько юрлиц по ИНН или два разных ОГРН с карт не должны становиться «не найдено» и не должны выбираться молча.

## What Changes

- После подтверждённых точек собрать юрполя: дата регистрации, статус, вид деятельности (ЕГРЮЛ); сигнал Федресурса; сигнал КАД по компании.
- Идентификатор: ОГРН или ИНН из зацепки, иначе ОГРН/ИНН с карточек карт. Учредителей не берём.
- Несколько юрлиц или два разных идентификатора с карт — список со ссылками и подтверждение. Первую запись не берём. Это не «не найдено».
- Нет идентификатора — юрполя «не найдено». Не писать «долгов нет» и «чисто».
- По каждому реестру один GET открытой страницы. Капча / 403 / пусто — только этот источник «не найдено», защиту не обходим.
- Сбой одной точки не валит две другие.
- В таблице — юрстроки со ссылкой или пометкой. Индекса 40/25/20/15 нет.

## Capabilities

### New Capabilities

- (нет) Логика живёт в `open-data-collect`.

### Modified Capabilities

- `open-data-collect`: юрполя, неоднозначность юрлица, один GET на реестр.
- `hook-intake`: после «готово к сбору» запрашиваются реестры; индекс по-прежнему запрещён.
- `project-bootstrap`: таблица может показать юрполя; совет «покупай» запрещён.

## Impact

- Код: резолв ОГРН/ИНН, порты поиска/разбора реестров, фикстуры, строки в Streamlit.
- Новых зависимостей нет. Тесты без сети.
- Не входит: формула устойчивости, SQLite, правка недостоверности, ФССП по людям.
