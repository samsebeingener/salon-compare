# Proposal: add-open-data-collect

## Why

Три зацепки уже принимаются, но полей с карт ещё нет. Без каскада «API → один GET HTML → не найдено» нельзя честно сравнить точки и нельзя показать, что один молчащий источник не валит всю тройку.

## What Changes

- После статуса «готово к сбору» собрать поля по каждой из трёх точек независимо.
- На каждое поле: сначала JSON API 2ГИС и Яндекс, если значения нет — один GET открытой HTML-страницы карточки, иначе «не найдено». Не ноль и не среднее.
- Капча, логин, 403 на HTML — шаг HTML сразу провал, защиту не обходим.
- Соседи ~500 м: сначала API радиуса, дырка — HTML; в поле число и «рейтинг выше/ниже», либо «не найдено».
- Сайт студии: один GET; закрыт — «не найдено».
- В интерфейсе — таблица найденных полей со ссылкой или пометкой «не найдено». Индекса привлекательности и вывода модели нет.
- Тесты только на фикстурах, без сети.
- Зависимости: `httpx`, `pydantic` (разбор HTML-извлечения в схему).

## Capabilities

### New Capabilities

- `open-data-collect`: каскад API/HTML, независимость трёх точек, соседи, сайт.

### Modified Capabilities

- `hook-intake`: после «готово к сбору» запускается сбор полей (не ЕГРЮЛ и не индекс).
- `project-bootstrap`: интерфейс может показать таблицу полей; сравнительный индекс и совет модели по-прежнему запрещены.

## Impact

- Код: порты API/HTML, каскад полей, фикстуры pytest, три колонки в Streamlit.
- Ключи `TWOGIS_API_KEY` / `YANDEX_MAPS_API_KEY` уже в `.env.example`.
- Не входит: ЕГРЮЛ, Федресурс, КАД, формула 40/25/20/15, SQLite, правка недостоверности.
