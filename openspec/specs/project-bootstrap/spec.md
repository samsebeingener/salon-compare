## Purpose

Каркас репозитория salon-compare: одна команда качества, Docker Compose, секреты в образце окружения, hello Streamlit без сбора салонов.

## Requirements

### Requirement: Одна команда качества ruff, mypy и pytest
Система SHALL предоставлять одну локальную команду, которая последовательно запускает ruff, mypy и pytest. GitHub Actions MUST вызывать ту же команду, без отдельного набора проверок. Прогон pytest MUST включать отчёт покрытия (`pytest-cov`) по пакету приложения. Команда и конфиг MUST NOT задавать `--cov-fail-under` и MUST NOT падать только из‑за процента покрытия.

#### Scenario: Локальный прогон качества
- GIVEN зависимости проекта установлены
- WHEN запускают единственную команду качества
- THEN выполняются ruff, mypy и pytest
- THEN pytest печатает отчёт покрытия
- THEN при успешных проверках команда завершается с кодом 0 даже если покрытие не 100%

#### Scenario: CI совпадает с локальной командой
- GIVEN открыт pull request или push в ветку с workflow
- WHEN GitHub Actions выполняет job качества
- THEN вызывается та же команда качества, что и локально
- THEN тесты в этом прогоне не обращаются к сети
- THEN в аргументах pytest нет `--cov-fail-under`

### Requirement: Docker Compose поднимает приложение без ключа модели
Система SHALL поднимать hello-приложение через Docker Compose, даже если переменные `LLM_*` отсутствуют или пустые. Отсутствие ключа модели MUST NOT блокировать старт каркаса.

#### Scenario: Старт без ключа модели
- GIVEN в окружении нет заполненных переменных `LLM_*`
- WHEN выполняют `docker compose up`
- THEN контейнер приложения стартует
- THEN процесс не падает из-за отсутствия ключа модели

### Requirement: Секреты не в git, образец окружения есть
Система MUST не включать `.env` в git. Репозиторий SHALL содержать отслеживаемый `.env.example` с плейсхолдером `TWOGIS_API_KEY`, переменными `LLM_*`, `HTTP_PROXY` и `HTTPS_PROXY`, а также **необязательными** плейсхолдерами `YANDEX_MAPS_JS_API_KEY` и `YANDEX_GEOCODER_API_KEY` (только визуализация карты в Streamlit, см. `streamlit-ui`). Система MUST NOT требовать ключ Яндекс Карт для сбора (`YANDEX_MAPS_API_KEY` отсутствует). Viz-ключи MUST NOT быть обязательными для старта приложения. Docker Compose SHALL передавать в контейнер `TWOGIS_API_KEY`, переменные `LLM_*` и MAY передавать `YANDEX_MAPS_JS_API_KEY` / `YANDEX_GEOCODER_API_KEY` из окружения или файла `.env`.

#### Scenario: .env не коммитится
- GIVEN в рабочей копии есть файл `.env` с любыми значениями
- WHEN проверяют индекс git и правила игнорирования
- THEN `.env` не предназначен для коммита

#### Scenario: .env.example содержит ключи каркаса
- GIVEN клонированный репозиторий без локального `.env`
- WHEN открывают `.env.example`
- THEN файл есть в git
- THEN в нём есть `TWOGIS_API_KEY`, переменные с префиксом `LLM_`, `HTTP_PROXY` и `HTTPS_PROXY`
- THEN в нём есть `YANDEX_MAPS_JS_API_KEY` и `YANDEX_GEOCODER_API_KEY` как необязательные
- THEN в нём нет `YANDEX_MAPS_API_KEY`

#### Scenario: Compose прокидывает ключ карт
- GIVEN заполненный `.env` с ключом 2ГИС
- WHEN поднимают приложение через Docker Compose
- THEN контейнер получает `TWOGIS_API_KEY`
- THEN контейнер MAY получить `YANDEX_MAPS_JS_API_KEY` и `YANDEX_GEOCODER_API_KEY`
- THEN `YANDEX_MAPS_API_KEY` в compose нет

### Requirement: Прокси для LLM из РФ
Система SHALL читать `HTTP_PROXY` и `HTTPS_PROXY` из окружения. Клиент к модели MUST передавать `trust_env=True`, чтобы при недоступности LLM из РФ работал прокси. Пустые значения MUST означать работу без прокси. README SHALL описывать эти переменные.

#### Scenario: Образец и клиент уважают прокси
- GIVEN в `.env.example` есть `HTTP_PROXY` и `HTTPS_PROXY`
- WHEN собирают HTTP-клиент для модели
- THEN клиент доверяет переменным окружения (`trust_env`)
- THEN в README указано, зачем прокси нужен из РФ

### Requirement: Streamlit отвечает по HTTP после Compose
После успешного `docker compose up` система SHALL принимать HTTP-запрос к опубликованному порту Streamlit и отвечать без ошибки соединения.

#### Scenario: HTTP после compose
- GIVEN `docker compose up` завершил старт приложения
- WHEN клиент делает HTTP-запрос к опубликованному порту Streamlit
- THEN соединение устанавливается
- THEN ответ не является ошибкой недоступности сервиса

### Requirement: Каркас — hello, без сбора салонов
Интерфейс SHALL принимать три зацепки и MAY показать таблицу собранных полей со ссылкой или «не найдено», включая юрполя. Система MAY открыть сохранённый разбор без нового поиска и без ключа модели. Система MUST NOT строить индекс привлекательности и MUST NOT выдавать вывод модели как инвестиционный совет. README SHALL кратко фиксировать живой прогон: 404 демо-пути сайта, реестры-оболочки без обхода капчи, ключи карт для JSON API.

#### Scenario: Нет сбора салонов
- GIVEN запущенное приложение
- WHEN пользователь открывает интерфейс и успешно разбирает три разные зацепки
- THEN видны поля для трёх зацепок
- THEN видна таблица полей или пометки «не найдено»
- THEN нет индекса привлекательности и нет совета «покупай»

#### Scenario: README описывает прогон
- GIVEN клонированный репозиторий
- WHEN открывают README
- THEN есть пометка про 404 пути Pinklemon и про оболочки реестров

#### Scenario: Открыть сохранённый разбор
- GIVEN в SQLite есть запись
- WHEN пользователь выбирает её и открывает
- THEN видна таблица
- THEN в интерфейсе сказано, что нового поиска нет
- THEN ключ LLM не требуется

### Requirement: Файл SQLite не коммитится
Система SHALL хранить разборы в одном файле SQLite в `data/` рядом с проектом. Git MUST игнорировать `*.db`, `*.sqlite`, `*.sqlite3` и содержимое `data/` кроме служебных заглушек.

#### Scenario: Файл базы вне git
- GIVEN рядом с проектом появился файл `*.sqlite` или `*.db`
- WHEN проверяют git status и `.gitignore`
- THEN файл базы не попадает в коммит

### Requirement: Тесты без сети
Тесты MUST выполняться без исходящих сетевых запросов. Ответы внешних систем SHALL подменяться фикстурами.

#### Scenario: Pytest без интернета
- GIVEN тестовый набор каркаса
- WHEN запускают pytest
- THEN прогон не ходит в интернет
- THEN внешние ответы, если фигурируют, берутся из фикстур

### Requirement: Слабая полка и описание fallback без ключа
Таблица MUST отличать полку «слабо» от «не найдено» и от подтверждённого первоисточника. README SHALL описать контур DuckDuckGo HTML → карточка rusprofile без API-ключа и паузу между запросами.

#### Scenario: Ячейка слабо
- GIVEN юрполе с полкой слабо и URL rusprofile
- WHEN рисуют таблицу
- THEN в ячейке есть значение, слово «слабо» и ссылка

#### Scenario: README без ключа rusprofile
- GIVEN README репозитория
- WHEN его читают
- THEN там есть DuckDuckGo, rusprofile и пауза
- THEN нет требования платного ключа rusprofile

### Requirement: README про живой POST DuckDuckGo
README SHALL кратко сказать, что поиск DuckDuckGo идёт POST и что JSON `has_captcha` на rusprofile не считается закрытой страницей.

#### Scenario: README после живого фикса
- GIVEN README репозитория
- WHEN его читают
- THEN есть POST и has_captcha либо «ложн» капч

### Requirement: README про каскад юрполей
README SHALL указать, что после пустого ЕГРЮЛ поля ищут на `companies.rbc.ru/search/?query={ОГРН}`, и только если карточки нет — DuckDuckGo→rusprofile.

#### Scenario: README знает РБК
- GIVEN README сдачи
- WHEN его читают
- THEN есть `companies.rbc.ru` и `query`

### Requirement: README сдачи без секретов
README SHALL описывать клон, `uv`, `docker compose up`, переменные `.env` без значений ключей и что без ключей 2ГИС/Яндекс демо-тройка из подготовки всё равно доходит до таблицы: поля карт «не найдено», юрблок по ОГРН не блокируется пустым поиском карт.

#### Scenario: Демо без ключей карт в README
- GIVEN README репозитория
- WHEN читают запуск
- THEN сказано, что ключи карт не обязательны, чтобы увидеть таблицу по трём зацепкам
- THEN нет подставленных значений ключей

### Requirement: Streamlit читает .env без стороннего пакета
При старте Streamlit-приложения система SHALL загрузить файл `.env` из корня проекта, если он есть. Загрузка MUST использовать стандартную библиотеку, без новой зависимости. Переменная, уже заданная в окружении непустым значением, MUST NOT перезаписываться из файла. Отсутствующий файл MUST не мешать старту. Значения ключей MUST NOT попадать в git.

#### Scenario: Файл задаёт ключ карт
- GIVEN временный `.env` с `TWOGIS_API_KEY` и пустой словарь окружения
- WHEN загружают файл
- THEN в окружении этот ключ заполнен
- THEN живой `.env` репозитория в тесте не читается

#### Scenario: Окружение уже задано
- GIVEN в окружении ключ уже непустой и в файле другое значение
- WHEN загружают файл
- THEN остаётся значение из окружения

#### Scenario: Приложение вызывает загрузку
- GIVEN исходник Streamlit
- WHEN проверяют старт
- THEN есть вызов загрузки `.env` из корня проекта

### Requirement: Интерфейс трёх зацепок без совета покупать
Интерфейс SHALL принимать три зацепки и MAY показать таблицу собранных полей, частичный индекс 40/25/20/15, три карточки салона, вывод модели и список сохранённых разборов. После отчёта SHALL показать расход запуска: токены и стоимость либо «не найдено». Экран «Расход» SHALL отражать сумму токенов и стоимости всех успешных вызовов модели в этом разборе, MUST NOT показывать только последний вызов после правки ячейки. README сдачи SHALL содержать укладку кода, сущности SQLite, границы и абзац про агента. README MUST не числить часы/90 дней/токены как несделанные дырки. Вывод модели MUST быть подписан как «текст модели, не инвестиционный совет». Система MUST NOT выдавать вывод как инвестиционный совет и MUST NOT писать «покупай».

#### Scenario: Экран расхода
- GIVEN три точки собраны
- WHEN смотрят отчёт
- THEN есть строка про токены или пометка, что расход не найден

#### Scenario: Экран расхода после повторного вердикта
- GIVEN разбор уже показал токены первого вызова модели
- AND пользователь правил ячейку и модель ответила снова с ненулевым usage
- WHEN смотрят блок «Расход»
- THEN токены и стоимость — сумма обоих успешных вызовов, не только последнего

#### Scenario: Экран после сбора
- GIVEN три разные зацепки доведены до сбора
- WHEN смотрят отчёт
- THEN в таблице есть строка индекса или пометка «не найдено»
- THEN есть карточки точек
- THEN подпись вывода модели не выдаёт его за инвестиционный совет
- THEN нет совета «покупай»

#### Scenario: Экран сдачи
- GIVEN клон репозитория и `docker compose up`
- WHEN открывают приложение
- THEN есть три поля зацепок
- THEN после разбора есть отчёт
- THEN сохранённый разбор можно открыть без нового поиска

### Requirement: README про сквозные источники
README SHALL сказать, что зацепка — только вход, дальше карты/сайт/РБК используются вместе; сайт с 2ГИС не выкидывают; ОГРН ищет карты по бренду РБК.

#### Scenario: README не обещает отрезанный каскад
- GIVEN README
- WHEN его читают
- THEN есть 2ГИС и бренд/сайт, нет формулы «только сайт значит без карт»

### Requirement: README фиксирует живой прогон сайта и ЕГРЮЛ
README SHALL записать: путь без `.html` даёт 404, живая страница — с `.html`; 2ГИС на демо-карточках ОГРН не отдаёт; без ОГРН юрполя пустые; поиск РБК по названию салона не используем.

#### Scenario: В README есть вечерний прогон
- GIVEN корневой README
- WHEN его читают
- THEN есть `baumanskaya.html` и пометка, что без ОГРН ЕГРЮЛ пустой

### Requirement: README про сайт на карточке 2ГИС
README SHALL записать: в браузере на карточке сайт виден; Places без `contact_groups` его не отдаёт; бот-GET 2gis.ru даёт 403 или `/museum`.

#### Scenario: README говорит про карточку 2ГИС
- GIVEN корневой README
- WHEN его читают
- THEN есть `contact_groups` и `museum`

### Requirement: Compose публикует Streamlit только на loopback
Docker Compose SHALL публиковать порт Streamlit как `127.0.0.1:8501:8501`. Система MUST NOT публиковать `8501:8501` на все интерфейсы хоста. Локальный HTTP-клиент к `http://127.0.0.1:8501` MUST по-прежнему достучаться до health и UI.

#### Scenario: Bind только localhost
- GIVEN файл Compose в корне репозитория
- WHEN читают публикацию портов сервиса приложения
- THEN есть `127.0.0.1:8501:8501`
- THEN нет голого `8501:8501` без адреса хоста

#### Scenario: Health с loopback
- GIVEN `docker compose up` завершил старт приложения
- WHEN клиент на той же машине запрашивает `http://127.0.0.1:8501/_stcore/health`
- THEN соединение устанавливается

### Requirement: Поля thinking модели только для хостов Kie
Клиент чата SHALL включать `include_thoughts` и `reasoning_effort` в JSON-тело запроса только если хост `LLM_BASE_URL` — `api.kie.ai` или заканчивается на `.kie.ai`. Для прочих хостов (в том числе OpenRouter и OpenAI-совместимых) эти ключи MUST отсутствовать. Значения на Kie: `include_thoughts` ложь, `reasoning_effort` `low`. `stream` MUST быть ложь на любом хосте.

#### Scenario: Kie получает thinking-поля
- GIVEN `LLM_BASE_URL` с хостом `api.kie.ai`
- WHEN собирают тело chat completions
- THEN в теле есть `include_thoughts` = ложь
- THEN в теле есть `reasoning_effort` = `low`
- THEN `stream` ложь

#### Scenario: OpenRouter без thinking-полей
- GIVEN `LLM_BASE_URL` с хостом не из `*.kie.ai`
- WHEN собирают тело chat completions
- THEN ключей `include_thoughts` и `reasoning_effort` нет
- THEN `stream` ложь
