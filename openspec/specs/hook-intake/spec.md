## Purpose

Приём трёх зацепок на запуск: распознать тип, не угадывать точку при нескольких кандидатах, не сравнивать объект с самим собой.

## Requirements

### Requirement: Три непустые зацепки на запуск
Система SHALL принимать запуск только если пользователь передал ровно три непустые зацепки. Пустая строка MUST не считаться зацепкой. Меньше или больше трёх непустых MUST останавливать разбор с понятным сообщением, без угадывания недостающих точек.

#### Scenario: Ровно три зацепки
- GIVEN три непустые строки (сайт, название, ОГРН)
- WHEN запускают разбор зацепок
- THEN все три принимаются к классификации
- THEN разбор не требует четвёртую зацепку

#### Scenario: Не три зацепки
- GIVEN две непустые строки и одна пустая
- WHEN запускают разбор зацепок
- THEN статус не «готово к сбору»
- THEN пользователь видит, что нужны три зацепки

### Requirement: Распознавание типа зацепки без модели
Система SHALL классифицировать каждую зацепку по содержимому, без вызова LLM. Поддерживаемые типы MUST включать: сайт, название, ОГРН, ИНН, ссылка на карты, ссылка на онлайн-запись, свободный текст.

#### Scenario: Демо-тройка из подготовки
- GIVEN `https://pinklemon-nails.ru/baumanskaya`, `Вишня Таганская` и `1147746349552`
- WHEN классифицируют зацепки
- THEN первая имеет тип сайта
- THEN вторая имеет тип названия
- THEN третья имеет тип ОГРН

#### Scenario: ИНН, карта и обрывок текста
- GIVEN десятизначный ИНН, ссылка на Яндекс Карты или 2ГИС и длинная свободная фраза
- WHEN классифицируют зацепки
- THEN типы соответственно ИНН, ссылка на карты и свободный текст

### Requirement: Неоднозначность — список со ссылками, без выбора за пользователя
Живой резолвер SHALL искать точки в API карт по типу зацепки. Если по зацепке не ровно одна карточка и поиск вернул несколько хитов, система MUST NOT выбирать точку, MUST NOT помечать поля «не найдено» из‑за нескольких хитов и MUST NOT подставлять fallback. Система SHALL показать все найденные карточки со ссылками и дождаться подтверждения пользователя. Сбор полей MUST NOT начинаться, пока каждая зацепка не сведена к одной точке. Интерфейс MUST NOT подставлять первую карточку списка, если пользователь ничего не выбрал. Если поиск вернул ноль карточек, система SHALL дать одну синтетическую точку для сайта, ссылки записи, ОГРН, ИНН, названия и свободного текста (id по типу зацепки). Ссылка на карты MUST резолвиться из URL, без каталога.

#### Scenario: Несколько похожих салонов
- GIVEN зацепка-название, по которой поиск карт вернул две карточки со ссылками
- WHEN запускают разбор зацепок
- THEN статус «нужно уточнение»
- THEN в ответе есть оба кандидата и их ссылки
- THEN нет выбранной точки «по умолчанию»
- THEN таблица полей ещё не строится
- THEN синтетический fallback для названия не создаётся

#### Scenario: Пользователь подтвердил карточку из списка
- GIVEN статус уточнения и две карточки по одной зацепке
- WHEN пользователь указывает id одной карточки
- THEN эта зацепка считается однозначной
- THEN если остальные слоты однозначны и id различны — статус «готово к сбору»

#### Scenario: Ни одного кандидата
- GIVEN зацепка сайта, ОГРН или названия, по которой поиск карт вернул пустой список
- WHEN запускают разбор зацепок
- THEN система даёт одну синтетическую точку по типу зацепки
- THEN слот считается однозначным без «нужно уточнение» из‑за пустого каталога

#### Scenario: Пустой radio не берёт первую карточку
- GIVEN две карточки в списке и нет выбранного id
- WHEN подтверждают точки
- THEN статус остаётся «нужно уточнение»
- THEN первая карточка не считается выбранной

#### Scenario: Демо-тройка без карточек карт
- GIVEN `https://pinklemon-nails.ru/baumanskaya`, `Вишня Таганская` и `1147746349552`, и оба каталога карт пустые
- WHEN запускают разбор зацепок
- THEN статус «готово к сбору»
- THEN три разных id: сайт, название, ОГРН
- THEN первую карточку карт система не выбирала — карточек не было

### Requirement: Две зацепки — одна точка
Если две принятые зацепки резолвер связал с одним и тем же идентификатором точки, система MUST NOT сравнивать объект с самим собой. Система SHALL сообщить, что это одна точка, показать ссылки и попросить заменить одну из трёх зацепок.

#### Scenario: Сайт и ОГРН одной студии
- GIVEN три зацепки, из которых две резолвер сводит к одному id точки
- WHEN запускают разбор зацепок
- THEN статус «дублирующиеся точки»
- THEN в ответе есть ссылки на совпавшую точку
- THEN нет статуса «готово к сбору» для этой тройки

### Requirement: Готовность к сбору карт, реестров и индекса
Когда три зацепки однозначно указывают на три разные точки, система SHALL пометить запуск готовым к сбору, SHALL собрать открытые поля и SHALL посчитать индекс 40/25/20/15 с честными дырами. Система MUST NOT выдавать совет «покупай».

#### Scenario: Три разные точки
- GIVEN три зацепки, каждая с ровно одним кандидатом, и три разных id
- WHEN запускают разбор зацепок и сбор
- THEN статус «готово к сбору»
- THEN по точкам есть собранные поля или «не найдено», включая юрполя при наличии ОГРН
- THEN есть индекс или честная пометка, что его нельзя считать

### Requirement: ОГРН ищет карты по бренду РБК, не только по цифрам
Если поиск карт по цифрам ОГРН пуст, система SHALL взять имя бренда с карточки РБК этого ОГРН и поискать 2ГИС/Яндекс по этому имени. Несколько карточек MUST показать на подтверждение, первую MUST NOT брать. Поиск РБК по общему словосочетанию вроде «ногтевой сервис» MUST NOT подставлять юрлицо автоматически.

#### Scenario: Цифры пусты, бренд нашёл две точки 2ГИС
- GIVEN ОГРН `1147746349552`, поиск карт по цифрам пуст, бренд «I LIKE NAILS», 2ГИС вернул две фирмы
- WHEN разбирают зацепку
- THEN статус уточнения, не READY
- THEN обе ссылки 2ГИС видны

#### Scenario: Цифры пусты, бренд нашёл одну точку
- GIVEN те же цифры пусты и одна карточка 2ГИС по бренду
- WHEN разбирают зацепку
- THEN эта карточка в кандидатах слота ОГРН

### Requirement: Подпись карточки в уточнении включает адрес
Если по зацепке несколько карточек карт, система SHALL показать для каждой не только название и ссылку, но и адрес из ответа поиска, когда он есть. Несколько филиалов с одним названием MUST различаться адресом. Если адреса в ответе нет, система MUST NOT выдумывать его и MUST оставить название со ссылкой.

#### Scenario: Сеть с одним названием и разными адресами
- GIVEN поиск вернул две карточки с названием «I like nails, студия маникюра» и адресами «Москва, Бауманская» и «Москва, Таганская»
- WHEN показывают список уточнения
- THEN в подписи первой карточки есть «Москва, Бауманская»
- THEN в подписи второй карточки есть «Москва, Таганская»
- THEN обе ссылки карт остаются в подписи

#### Scenario: Адрес в поиске пустой
- GIVEN две карточки с одним названием и без адреса в ответе поиска
- WHEN показывают список уточнения
- THEN подпись содержит название и ссылку
- THEN в подписи нет выдуманного адреса

### Requirement: Подпись уточнения включает этаж и ТЦ
Если в ответе поиска 2ГИС есть комментарий адреса (этаж, вход) или имя здания (ТЦ), система SHALL включить их в адрес карточки в списке уточнения вместе с улицей. Текст, который уже есть в улице, MUST NOT дублироваться. Если комментария и здания нет, система MUST оставить улицу как есть и MUST NOT выдумывать этаж или ТЦ.

#### Scenario: Этаж и ТЦ в хите 2ГИС
- GIVEN карточка с улицей «Москва, Бауманская, 7», комментарием «1 этаж» и зданием «ТЦ Атриум»
- WHEN показывают список уточнения
- THEN в подписи есть «Москва, Бауманская, 7»
- THEN в подписи есть «ТЦ Атриум»
- THEN в подписи есть «1 этаж»

#### Scenario: Комментария нет
- GIVEN карточка только с улицей «Москва, Таганская»
- WHEN показывают список уточнения
- THEN в подписи есть «Москва, Таганская»
- THEN в подписи нет выдуманного этажа или ТЦ
