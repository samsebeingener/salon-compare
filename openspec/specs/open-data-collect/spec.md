## Purpose

Сбор открытых полей трёх точек: каскад API карт, затем один HTML, иначе «не найдено». Точки независимы. Капчу не обходим.

## Requirements

### Requirement: Каскад поля API затем HTML затем не найдено
Для каждого сравниваемого поля системы карт система SHALL сначала взять значение из JSON API 2ГИС. Система MUST NOT вызывать Яндекс Places / ППО (`search-maps.yandex.ru`) и MUST NOT хранить поля `yandex_*`. Если поля нет в ответе 2ГИС (пусто, нет ключа, ошибка запроса), система SHALL сделать не больше одного GET открытой HTML-страницы той же карточки 2ГИС. Если HTML не дал поле — значение MUST быть «не найдено», без нуля и без среднего. Сбор SHALL загружать карточку по идентификатору уже выбранной точки. Несколько результатов поиска на шаге зацепок MUST NOT превращаться в «не найдено» на шаге полей.

#### Scenario: Полный ответ API
- GIVEN фикстура API 2ГИС с рейтингом и числом отзывов
- WHEN собирают поля точки
- THEN рейтинг 2ГИС заполнен из API со ссылкой источника
- THEN HTML для этого поля не вызывается

#### Scenario: В API нет рейтинга, HTML отдал
- GIVEN API 2ГИС без рейтинга и HTML карточки с рейтингом
- WHEN собирают поля точки
- THEN рейтинг 2ГИС берётся из HTML со ссылкой страницы
- THEN поле не заполняется нулём

#### Scenario: API пусто и HTML закрыт
- GIVEN пустой API 2ГИС и HTML с капчей, логином или 403
- WHEN собирают поля точки
- THEN рейтинг и отзывы 2ГИС имеют пометку «не найдено»
- THEN значение не подменяется нулём или средним
- THEN защиту (капча/логин) не обходят повторными запросами

#### Scenario: Поиск нашёл несколько карточек
- GIVEN поиск по зацепке вернул больше одной карточки 2ГИС
- WHEN ещё нет подтверждения пользователя
- THEN поля не заполняются как «не найдено» из‑за числа хитов
- THEN сначала запрашивается подтверждение со ссылками

### Requirement: Три точки независимо
Сбой или пустые поля одной точки MUST NOT отменять сбор двух других. Система SHALL вернуть запись по каждой из трёх точек. Если сбор одной точки прервался исключением, эта запись MUST быть помечена как сбой сбора (`collect_ok` ложь и краткое `collect_error`), MUST NOT выглядеть как успешный прогон со всеми полями «не найдено» без следа сбоя. Две другие точки SHALL собираться как обычно.

#### Scenario: Один источник молчит у одной точки
- GIVEN у первой точки API 2ГИС пуст, у второй и третьей API полон
- WHEN собирают три точки
- THEN первая точка остаётся в результате с дырками «не найдено» где пусто
- THEN у первой точки `collect_ok` истина (нет исключения)
- THEN вторая и третья точки собраны
- THEN запуск не останавливается целиком

#### Scenario: Исключение на одной точке
- GIVEN `collect_place` для второй точки поднимает `TypeError`, первая и третья завершаются без исключения
- WHEN собирают три точки
- THEN в результате три записи
- THEN у второй `collect_ok` ложь и непустое `collect_error` с типом исключения
- THEN у первой и третьей `collect_ok` истина
- THEN прогон не останавливается целиком

### Requirement: Соседи в радиусе 500 м
Система SHALL собрать число похожих студий в ~500 м и одну строку: их средний рейтинг выше или ниже нашей точки. Сначала API радиуса по координатам точки; если поля нет — один GET HTML. Иначе «не найдено». Число соседей MUST NOT подменяться нулём, если данных нет. Запрос карточки 2ГИС SHALL включать координаты (`items.point`), если ключ позволяет.

#### Scenario: Соседи из API
- GIVEN API радиуса вернул число соседей и средний рейтинг выше нашей точки
- WHEN собирают поля точки
- THEN есть число соседей и пометка «выше»
- THEN HTML соседей не вызывается

#### Scenario: Соседей нет в API и HTML закрыт
- GIVEN API радиуса без числа соседей и HTML с 403
- WHEN собирают поля точки
- THEN соседи — «не найдено», не ноль

#### Scenario: Нет координат — соседи не рисуются
- GIVEN карточка без точки на карте
- WHEN собирают поля
- THEN соседи — «не найдено», не ноль

### Requirement: Сайт студии один GET
Если у точки есть URL сайта, система SHALL сделать один GET открытой страницы. Капча, логин-стена или 403 MUST дать «не найдено» для полей сайта. HTTP 404 MUST дать «не найдено». Успешный GET MAY заполнить краткое «о нас», если разбор HTML (схема Pydantic) это вернул. GET SHALL отправлять User-Agent браузера.

#### Scenario: Сайт открылся
- GIVEN URL сайта и HTML без защиты, парсер вернул текст «о нас»
- WHEN собирают поля точки
- THEN поле сайта заполнено со ссылкой на URL
- THEN повторного GET нет

#### Scenario: Сайт закрыт
- GIVEN URL сайта и ответ 403
- WHEN собирают поля точки
- THEN поле сайта — «не найдено»

#### Scenario: Сайт 404
- GIVEN URL сайта и ответ 404
- WHEN собирают поля точки
- THEN поле сайта — «не найдено»

### Requirement: Старый разбор без Яндекса
`load_run` SHALL открыть payload, в котором есть ключи `yandex_*` или их нет. Лишние ключи Яндекса MUST игнорироваться. Отсутствие полей Яндекса MUST NOT ронять разбор.

#### Scenario: Payload со старыми полями Яндекса
- GIVEN SQLite JSON точки с `yandex_rating` и без обязательности этих полей в текущей схеме
- WHEN открывают сохранённый разбор
- THEN запись загружается
- THEN колонок Яндекса в новой таблице нет

### Requirement: Оболочка реестра без идентификатора не заполняет поля
Если HTML реестра открылся, но в теле нет запрошенного ОГРН или ИНН, система MUST поставить «не найдено». Система MUST NOT выводить «есть дела», «не обнаружено», «банкротство» по общим словам оболочки (арбитраж, войти, торги).

#### Scenario: ЕГРЮЛ-капча без ОГРН в теле
- GIVEN HTML ЕГРЮЛ со словом captcha и без ОГРН
- WHEN собирают юрполя
- THEN поля ЕГРЮЛ — «не найдено»

### Requirement: Федресурс и КАД не запрашиваются
Сбор полей MUST NOT делать GET на `fedresurs.ru` и `kad.arbitr.ru`. Поля Федресурс и КАД в отчёте MUST быть «не найдено» либо скрыты. Устойчивость индекса MUST NOT ждать эти сайты. ИНН (10 или 12 цифр) MUST NOT подменять ОГРН в запросах судебных реестров.

#### Scenario: ОГРН собирает только ЕГРЮЛ-каскад
- GIVEN зацепка ОГРН и фикстура HTML ЕГРЮЛ
- WHEN собирают поля точки
- THEN дата/статус/деятельность могут заполниться
- THEN URL Федресурса и КАД отсутствуют в запросах

#### Scenario: На карте только ИНН
- GIVEN карточка с ИНН без ОГРН
- WHEN собирают юрполя
- THEN запроса Федресурса и КАД с этим ИНН нет

### Requirement: Слово войти не закрывает страницу
Классификация HTML SHALL считать страницу закрытой при 401/403/429 или маркере капчи. Слово «войти» в меню MUST NOT само по себе давать статус закрыто.

#### Scenario: Сайт 200 с кнопкой Войти
- GIVEN HTML статус 200 с текстом «Войти» и без капчи
- WHEN классифицируют ответ
- THEN статус не blocked

#### Scenario: 403 остаётся закрытым
- GIVEN HTML статус 403
- WHEN классифицируют ответ
- THEN статус blocked

### Requirement: Fallback ЕГРЮЛ через DuckDuckGo и карточку rusprofile
Если у точки есть ровно один ОГРН и официальный HTML ЕГРЮЛ не дал дату, статус и вид деятельности, система SHALL сделать один GET HTML-поиска DuckDuckGo без API-ключа по запросу этого ОГРН и `site:rusprofile.ru/id`. Система SHALL открывать найденные URL вида `rusprofile.ru/id/{цифры}` по очереди, не больше пяти. Значение MUST попасть в отчёт только если тело карточки содержит этот ОГРН. Первую ссылку выдачи без сверки брать MUST NOT. Поля MUST иметь полку «слабо» и ссылку на карточку rusprofile, не на DuckDuckGo. Система MUST NOT снимать учредителей и ФИО. Федресурс и КАД MUST NOT заполняться из страницы rusprofile. Капча или 403 на поиске или карточке MUST дать «не найдено» для этих полей ЕГРЮЛ; защиту не обходить повторными запросами. Если официальный ЕГРЮЛ уже заполнил хотя бы одно поле, поиск DuckDuckGo MUST NOT вызываться.

#### Scenario: ЕГРЮЛ пуст, поиск и карточка совпали по ОГРН
- GIVEN ОГРН `1147746349552`, официальный ЕГРЮЛ без полей, фикстура DuckDuckGo со ссылкой `rusprofile.ru/id/7301223` и HTML карточки с этим ОГРН, датой, статусом и видом деятельности
- WHEN собирают юрполя
- THEN дата, статус и вид деятельности заполнены
- THEN источник — URL карточки rusprofile
- THEN полка поля — слабо
- THEN Федресурс и КАД не берутся из этой карточки

#### Scenario: Первая ссылка без ОГРН, вторая с ОГРН
- GIVEN выдача DuckDuckGo с двумя `/id/`, первая карточка без запрошенного ОГРН, вторая с ОГРН и полями
- WHEN собирают юрполя
- THEN поля берутся со второй карточки
- THEN первая карточка не становится источником

#### Scenario: Капча DuckDuckGo
- GIVEN официальный ЕГРЮЛ пуст и HTML DuckDuckGo со статусом закрыто (капча)
- WHEN собирают юрполя
- THEN поля ЕГРЮЛ — «не найдено»
- THEN запросов rusprofile нет
- THEN капчу не решают и не повторяют поиск

#### Scenario: Официальный ЕГРЮЛ уже отдал поля
- GIVEN HTML ЕГРЮЛ с ОГРН и заполненными полями
- WHEN собирают юрполя
- THEN источник полей ЕГРЮЛ — страница ФНС
- THEN DuckDuckGo не вызывается

### Requirement: Пауза между запросами DuckDuckGo и rusprofile
Между GET HTML-поиска DuckDuckGo и GET карточек rusprofile система SHALL выдерживать паузу в секундах (не ноль в приложении). Один объект паузы MUST действовать на все три точки одного прогона. В тестах пауза подменяется: реальной сети и реального sleep нет. Капчу пауза не обходит и не решает.

#### Scenario: Два paced-запроса подряд
- GIVEN fallback: сначала DuckDuckGo, затем одна карточка rusprofile
- WHEN собирают юрполя
- THEN между этими GET зафиксирована одна пауза
- THEN тест не вызывает сетевой sleep

#### Scenario: Три салона делят паузу
- GIVEN три точки с ОГРН и пустым официальным ЕГРЮЛ
- WHEN собирают три точки
- THEN паузы идут по цепочке запросов всех трёх точек, не с нуля на каждом салоне

### Requirement: DuckDuckGo HTML-поиск через POST
Запрос HTML-поиска DuckDuckGo (`html.duckduckgo.com`) SHALL выполняться методом POST с полем `q`, без GET той же страницы. Капчу MUST NOT решать. Если POST закрыт или пуст — поля ЕГРЮЛ с этого шага «не найдено».

#### Scenario: URL поиска DuckDuckGo уходит POST
- GIVEN URL `https://html.duckduckgo.com/html/?q=…`
- WHEN загрузчик открывает этот URL
- THEN вызывается POST с телом формы, содержащим исходный `q`
- THEN GET этой страницы не вызывается

### Requirement: JSON has_captcha не закрывает открытую карточку
Классификация HTML MUST NOT ставить «закрыто» только из‑за JSON-ключей `has_captcha` / `disable_captcha`. HTTP 200 с карточкой компании и этими ключами SHALL быть «ok». Маркер реальной капчи (`smartcaptcha`, `recaptcha`, `g-recaptcha`) или 401/403/429 MUST оставаться «закрыто».

#### Scenario: rusprofile с has_captcha в JSON
- GIVEN HTML статус 200, в теле ОГРН и «Действующая организация», в JSON `"has_captcha":true`
- WHEN классифицируют ответ
- THEN статус ok

#### Scenario: Настоящая smartcaptcha
- GIVEN HTML статус 200 со словом smartcaptcha
- WHEN классифицируют ответ
- THEN статус blocked

### Requirement: Статус и ОКВЭД с карточки, не с связей и меню
Разбор ЕГРЮЛ SHALL считать организацию действующей, если на карточке «действующая организация», даже если ниже есть «ликвидированных связанных организаций». Вид деятельности SHALL браться из «основной вид деятельности», не из первого «оквэд» в меню.

#### Scenario: Связанные ликвидированы, сама действует
- GIVEN HTML с «Действующая организация», датой регистрации, «Основной вид деятельности Предоставление услуг парикмахерскими» и фразой «ликвидированных связанных организаций», плюс «оквэд» в меню раньше по тексту
- WHEN разбирают ЕГРЮЛ
- THEN статус «действует»
- THEN деятельность содержит парикмахерскими
- THEN деятельность не из меню оквэд

### Requirement: РБК Компании по ОГРН, если ЕГРЮЛ пуст
Если официальный ЕГРЮЛ не дал дату, статус и деятельность, система SHALL сделать один GET `https://companies.rbc.ru/search/?query={ОГРН}`. Поля MUST браться только из блока карточки, где есть этот ОГРН. Заголовок выдачи с тем же ОГРН MUST NOT считаться карточкой. Полка MUST быть «слабо», источник — URL поиска. Федресурс и КАД MUST NOT заполняться с РБК. Учредителей и ФИО MUST NOT копировать. Если карточки нет или страница закрыта, система MAY дальше искать через DuckDuckGo→rusprofile. Капчу MUST NOT решать. Если официальный ЕГРЮЛ уже заполнил поля, GET РБК MUST NOT вызываться.

#### Scenario: ЕГРЮЛ пуст, РБК отдал карточку
- GIVEN ОГРН `1147746349552`, ЕГРЮЛ закрыт, HTML поиска РБК с `company-card`, статусом «Действует», датой регистрации `01.04.2014` и тем же ОГРН
- WHEN собирают юрполя
- THEN статус «действует», дата `01.04.2014`, полка слабо, источник URL поиска РБК
- THEN DuckDuckGo и rusprofile не вызываются

#### Scenario: В выдаче только заголовок запроса
- GIVEN HTML поиска РБК с текстом «Результаты по запросу» и ОГРН, без блока карточки с этим ОГРН
- WHEN собирают юрполя
- THEN поля с РБК не заполнены
- THEN допускается следующий шаг rusprofile

#### Scenario: Официальный ЕГРЮЛ уже есть
- GIVEN ЕГРЮЛ вернул карточку с ОГРН
- WHEN собирают юрполя
- THEN URL поиска РБК не вызывается

### Requirement: Сбор не повторяется на rerun
Если в одной сессии уже собраны поля для тех же трёх точек и того же выбора юрлица, система MUST NOT вызывать `collect_three` повторно.

#### Scenario: Тот же ключ точек
- GIVEN сбор уже выполнен для набора venue_id и legal_choices
- WHEN интерфейс перерисовывается без смены точек и юрлица
- THEN повторного collect_three нет

### Requirement: Часы и свежесть с каскадом API затем HTML
Поля часов, даты последнего отзыва, «отзывы за 90 дней» и плюс/минус SHALL идти тем же каскадом, что рейтинг: сначала API, затем один HTML, иначе «не найдено».

#### Scenario: API без даты, HTML отдал
- GIVEN API без даты отзыва и HTML с datePublished
- WHEN собирают поля
- THEN дата последнего отзыва взята со страницы

### Requirement: Поиск 2ГИС ограничен Москвой
Текстовый поиск организаций в Catalog API 2ГИС (`/3.0/items` по полю `q`) SHALL передавать `region_id` региона Москва (`32`, как в документации Regions API). Поиск MUST NOT оставлять запрос без региона: иначе API возвращает «не найдено» даже при рабочем ключе. Загрузка карточки по id и поиск соседей по координатам MUST NOT требовать тот же `region_id`. Несколько найденных филиалов MUST по-прежнему уходить на подтверждение, без выбора первой карточки.

#### Scenario: Запрос по названию несёт регион Москвы
- GIVEN текстовый поиск 2ГИС по зацепке «Вишня Таганская»
- WHEN собирают параметры Catalog `/3.0/items`
- THEN в параметрах есть `q` с этой зацепкой
- THEN есть `region_id` равный `32`
- THEN живой HTTP в тесте не вызывается

#### Scenario: Клиент поиска передаёт регион в httpx
- GIVEN `TwoGisApi` и подмена HTTP-клиента
- WHEN вызывают search по строке
- THEN запрос к `/3.0/items` содержит `region_id=32`
- THEN сеть не открывается

### Requirement: Сайт и ОГРН с карточки карт при любой зацепке
Система SHALL забрать сайт (и часы, если они есть в JSON) с открытой карточки 2ГИС. Поле «о нас» MAY грузиться с этого сайта, даже если зацепка была ОГРН или название. Запрос 2ГИС MUST включать contact_groups и org, чтобы сайт и ОГРН не отбрасывались. Нет сайта в JSON и зацепка не URL — «о нас» MUST быть «не найдено», не выдумка.

#### Scenario: ОГРН, в 2ГИС есть сайт
- GIVEN зацепка ОГРН и JSON 2ГИС с website `https://studio.example`
- WHEN собирают поля
- THEN HTML сайта запрашивается
- THEN «о нас» со ссылкой на этот URL, если парсер вернул текст

#### Scenario: Сайт в JSON 2ГИС
- GIVEN item 2ГИС с contact type website
- WHEN разбирают карточку
- THEN `website` заполнен, `html_url` остаётся ссылкой 2ГИС

### Requirement: Часы, район и метро из JSON Places
Система SHALL заполнить часы работы, район и ближайшее метро из JSON 2ГИС Places, если эти блоки есть в ответе. Часы MUST браться из `schedule`, район — из административного деления типа district, метро — из ближайшей станции с типом metro и расстоянием. Если блока нет, значение MUST быть «не найдено». Система MUST NOT выдумывать график, район или станцию.

#### Scenario: Полный JSON Places
- GIVEN карточка 2ГИС с графиком пн–вс 10:00–22:00, районом «Замоскворечье» и метро «Павелецкая» 140 м
- WHEN собирают поля точки
- THEN часы содержат 10:00 и 22:00
- THEN район — «Замоскворечье»
- THEN метро содержит «Павелецкая» и «140»

#### Scenario: В JSON нет графика и метро
- GIVEN карточка 2ГИС без `schedule` и без станций метро
- WHEN собирают поля точки
- THEN часы, район и метро — «не найдено», не ноль и не заглушка

### Requirement: HTML только по явным маркерам
Живой `OpenHtmlParser` SHALL заполнить `about`, `rating`, `review_count` и `address`, если в открытом HTML есть явный маркер. About MUST браться из JSON-LD `description`, иначе из `meta name="description"`, иначе из текста после заголовка «О нас» или «О студии» (не длиннее 280 символов). Rating и число отзывов MUST браться из JSON-LD `aggregateRating` (`ratingValue`, `reviewCount`). Адрес — из JSON-LD `address`. Нет маркера — поле MUST остаться пустым, без угадывания по CSS-классу вроде `class="rating"`. Соседей из HTML MUST NOT выдумывать.

#### Scenario: JSON-LD с описанием и рейтингом
- GIVEN HTML с JSON-LD: description «Студия у метро», aggregateRating 4.6 и reviewCount 80, PostalAddress
- WHEN парсят открытую страницу
- THEN about содержит «Студия у метро»
- THEN rating 4.6 и review_count 80
- THEN address не пустой

#### Scenario: Нет маркеров — не выдумывать
- GIVEN HTML только с `<div class="rating">4.6</div>`
- WHEN парсят
- THEN rating, about и plus_minus пустые

### Requirement: 404 сайта без расширения — один GET с .html
Если зацепка или сайт с карты — HTTP URL, последний сегмент пути без точки, и GET вернул статус `empty`, система SHALL сделать один GET того же URL с суффиксом `.html`. Успешный HTML MAY заполнить «о нас». Если исходный GET `ok` или `blocked`, суффикс MUST NOT запрашиваться. Капчу MUST NOT решать.

#### Scenario: Путь без расширения, 404, .html открылся
- GIVEN зацепка `https://pinklemon-nails.ru/baumanskaya` со статусом `empty` и `https://pinklemon-nails.ru/baumanskaya.html` со статусом `ok` и текстом «о нас»
- WHEN собирают поля точки
- THEN «о нас» взято с URL с `.html`
- THEN исходный 404 не маскируется нулём

#### Scenario: Сайт закрыт 403
- GIVEN тот же путь без расширения и статус `blocked`
- WHEN собирают поля точки
- THEN URL с `.html` не вызывается
- THEN «о нас» — «не найдено»

### Requirement: ОГРН с маркера на сайте, если карты молчат
Если у зацепки нет ОГРН, на карточке 2ГИС нет ОГРН, и в HTML сайта есть явная подпись «ОГРН» (или «ОГРН/ОГРНИП») и 13 либо 15 цифр, система SHALL собрать юрполя по этому номеру тем же каскадом, что и для зацепки-ОГРН. Голое 13-значное число без слова «ОГРН» MUST NOT становиться юрлицом.

#### Scenario: На сайте подписан ОГРН, на карте нет
- GIVEN сайт открылся, в теле «ОГРН 1147746349552», карточка 2ГИС без ОГРН
- WHEN собирают юрполя
- THEN вызывается каскад ЕГРЮЛ/РБК для `1147746349552`

#### Scenario: В HTML только длинные цифры без подписи
- GIVEN сайт с числом `1495810359387` без слова «ОГРН»
- WHEN собирают юрполя
- THEN юрполя «не найдено»
- THEN реестры по этому числу не вызываются

### Requirement: Сайт студии с HTML карточки 2ГИС
Если JSON 2ГИС не содержит website, система SHALL сделать один GET `html_url` карточки. Website MUST браться из явного маркера: JSON `"type":"website"` и url/value, иначе внешняя http(s)-ссылка не на хост 2ГИС и не соцсеть. Этот URL MAY дальше открываться для поля «о нас». Нет маркера или HTML закрыт — «о нас» MUST NOT выдумываться с домена 2gis.ru.

#### Scenario: В HTML карточки есть type website
- GIVEN JSON без contact_groups и HTML карточки с `"type":"website"` и `vishnyasalon.ru`
- WHEN собирают точку с зацепкой-названием
- THEN «о нас» грузится с `https://vishnyasalon.ru`, не с `2gis.ru`

#### Scenario: HTML карточки закрыт
- GIVEN GET карточки 2ГИС статус `blocked`
- WHEN собирают точку без URL в зацепке
- THEN отдельный сайт не угадывается
- THEN «о нас» — «не найдено»

### Requirement: 2gis.ru HTML без прокси LLM, museum закрыт
GET страницы `2gis.ru` (не Catalog API) MUST идти без `HTTP_PROXY`/`HTTPS_PROXY`. Если финальный путь `/museum`, статус MUST быть `blocked`.

#### Scenario: Редирект на museum
- GIVEN ответ 200 с URL path `/museum`
- WHEN классифицируют fetch
- THEN статус `blocked`

### Requirement: Поиск сайта через DDG при пустых картах
Если после зацепки, JSON 2ГИС и HTML карточки нет URL сайта, система SHALL один раз искать DuckDuckGo HTML по названию и адресу точки. Первые подходящие внешние http(s) URL MAY открываться для «о нас». Агрегаторы (Яндекс.Карты, Zoon, соцсети) MUST NOT подставляться как сайт студии.

#### Scenario: 2ГИС HTML blocked, DDG находит vishnyasalon.ru
- GIVEN карточка 2ГИС без website, GET карточки `blocked`
- AND DDG HTML содержит `result__a` на `https://vishnyasalon.ru/`
- WHEN собирают «Вишня Таганская» с адресом
- THEN «о нас» грузится с `vishnyasalon.ru`

### Requirement: Сайт с карточки РБК по ОГРН
При зацепке ОГРН система SHALL открыть карточку компании на РБК (из поиска по ОГРН) и взять URL из блока «Сайт» для поля «о нас».

#### Scenario: ОГРН → ilike-nails.ru с РБК
- GIVEN поиск РБК по ОГРН и id-страница с `Сайт` → `http://ilike-nails.ru`
- WHEN собирают точку с зацепкой ОГРН
- THEN URL студии открывается для «о нас»

### Requirement: ОГРН/ИНН на внутренних страницах сайта
Если на загруженной странице сайта нет labeled ОГРН/ИНН, система SHALL следовать по same-host ссылкам с path, содержащим контакты/политику/реквизиты (лимит GET), и искать labeled маркеры.

#### Scenario: ОГРН на /politica
- GIVEN главная без ОГРН, `/politica` с `ОГРН: 1234567890123`
- WHEN собирают сайт
- THEN `extra_ogrn` передаётся в юрблок

### Requirement: Сбой сбора виден в записи точки
`PlaceRecord` SHALL иметь `collect_ok` (по умолчанию истина) и `collect_error` (по умолчанию пусто). При исключении вокруг сбора точки система SHALL залогировать traceback (`logging.exception`) и вернуть каркас пустых полей с `collect_ok` ложь. `collect_error` MUST содержать тип исключения и краткий текст, MUST NOT содержать stack trace. Старый JSON без этих ключей SHALL разбираться через `coerce_place_record` как `collect_ok` истина и `collect_error` пусто.

#### Scenario: Исключение в collect_place
- GIVEN сбор точки поднимает исключение
- WHEN обрабатывают сбой в `collect_three`
- THEN запись точки с пустыми полями «не найдено»
- THEN `collect_ok` ложь
- THEN `collect_error` без traceback
- THEN в логе есть exception с traceback

#### Scenario: Старый payload без полей сбоя
- GIVEN JSON точки без `collect_ok` и `collect_error`
- WHEN вызывают `coerce_place_record`
- THEN запись загружается
- THEN `collect_ok` истина
- THEN `collect_error` пусто

### Requirement: Пустая карточка API не маскирует баг кода
Загрузка карточки 2ГИС MAY вернуть пустые поля, если API не ответил или сеть недоступна (`httpx`/`OSError`): это «не найдено», `collect_ok` остаётся истиной. Ошибка кода при разборе карточки (`TypeError`, `AttributeError` и прочие не-сетевые исключения) MUST всплыть из безопасной обёртки карточки в сбор точки и MUST быть помечена как сбой сбора, а не как пустая карточка без флага.

#### Scenario: Сеть при fetch карточки
- GIVEN `fetch_card` поднимает ошибку HTTP-клиента или `OSError`
- WHEN собирают точку
- THEN поля карт — «не найдено»
- THEN `collect_ok` истина
- THEN сбой залогирован

#### Scenario: Баг разбора карточки
- GIVEN `fetch_card` поднимает `TypeError` или `AttributeError`
- WHEN собирают три точки
- THEN эта точка с `collect_ok` ложь
- THEN исключение не превращено в молчаливую пустую `MapCard` без флага сбоя
