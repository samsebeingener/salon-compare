# salon-compare

Сравнение трёх маникюрных точек Москвы для инвестора: открытые данные, оценка привлекательности и честная достоверность.

Тестовое задание. После трёх разных зацепок показывается таблица полей: ссылка источника или «не найдено». Индекс привлекательности 50/25/25 (репутация / устойчивость / локация) частичный: нет данных ≠ ноль. Это ориентир, не совет покупать.

## Клонирование и запуск

```text
git clone https://github.com/samsebeingener/salon-compare.git
cd salon-compare
```

На Windows можно двойным щелчком запустить **`START.bat`**: проверит `.env`, спросит пустые ключи (значения не печатает), поднимет Docker Compose или локальный Streamlit и откроет http://127.0.0.1:8501. Нужны Python 3 и Docker Desktop; если `docker` недоступен — запасной запуск через `uv`. Повторный запуск снова проверяет файл и пустые поля.

Вручную:

```text
cp .env.example .env
uv sync --group dev
uv run python scripts/run_quality.py
uv run streamlit run src/salon_compare/app.py
```

Локальный Streamlit читает ключи из `.env` в корне проекта. Уже заданные переменные окружения не перезаписывает. В git файл `.env` не попадает.

Сдача заказчику (клон + `START.bat` или `.env` по образцу + одна команда):

```text
docker compose up --build
```

Приложение: http://127.0.0.1:8501 — ключ модели для разбора зацепок не нужен. Ключ 2ГИС тоже не обязателен, чтобы увидеть таблицу: без него демо-тройка (сайт, «Вишня Таганская», ОГРН `1147746349552`) всё равно доходит до сбора. Поля карт будут «не найдено»; юрблок по ОГРН карты не ждёт. Если поиск карт вернул несколько салонов — нужно подтвердить, первую не берём. После сбора разбор пишется в SQLite (`data/salon-compare.sqlite`): его можно открыть снова без нового поиска и без ключа модели. В таблице ячейка правится карандашом (иконка на наведении): значение пишется в тот же разбор, индекс 50/25/25 пересчитывается. В ячейке только значение и `[n]`, ссылки — сноски под таблицей; один URL — один номер. «Сайт о нас» сжимается до короткой строки, полный текст во всплывающей подсказке. Полка «слабо», источник «правка человека». Индекс руками не меняется. Точку можно пометить недостоверной в том же окне — она остаётся в таблице, её индекс не число. После таблицы — короткий вывод модели по уже посчитанным цифрам. Подпись: «текст модели, не инвестиционный совет». Без ключа LLM вывод пустой, приложение не падает.

## Как уложен код

Один процесс. Слои лежат плоско в `src/salon_compare/`, без микросервисов.

| Модуль | Зачем |
|---|---|
| `app.py` | Streamlit: три зацепки, подтверждение, таблица с правкой ячеек, вывод модели, список сохранённых разборов |
| `hooks.py`, `intake.py`, `resolver.py` | Тип зацепки и поиск точек на картах, без выбора «первой» |
| `maps_http.py`, `maps_parse.py`, `html_fetch.py` | JSON API 2ГИС и один GET открытой HTML-страницы |
| `collect.py`, `legal.py` | Поля точки и юрблок (ЕГРЮЛ, РБК Компании, Федресурс, КАД, запасной rusprofile) |
| `score.py` | Индекс 50/25/25, пустой блок не ноль |
| `report.py`, `llm.py` | Карточки, правки, разбор JSON модели |
| `store.py` | SQLite разборы |
| `load_env.py`, `proxy.py` | `.env` и `trust_env` для прокси |

Тесты в `tests/`, в интернет не ходят. Качество: `uv run python scripts/run_quality.py`.

## Что хранит SQLite

Один файл `data/salon-compare.sqlite` (в git не попадает). Одна таблица `runs`:

- `id` — номер разбора;
- `created_at` — время записи;
- `payload` — JSON трёх точек (поля, полки, ссылки, флаг недостоверности), плюс `usage` (токены/стоимость) и `verdict` (вывод модели).

Ключи API и модели в `payload` не пишутся. Старый разбор открывается без нового поиска и без нового вызова LLM: таблица, вывод модели и расход берутся из файла. Без сохранённого вывода — «в разборе не сохранялся», не повторный запрос к API.

## Как собираются поля

На экране три поля. Тип зацепки определяется без модели. Зацепка — только вход: дальше смотрим карты, сайт и юрреестры вместе. Поиск карт показывает все найденные карточки со ссылками: даже одну карточку подтверждаем, первую попавшуюся не берём. Нет нужного варианта — пункт в том же списке («нужный вариант не найден, попробуйте добавить иные зацепки»); остальные слоты не сбрасываются, сравнение идёт по выбранным точкам (нужны хотя бы две). С карточки 2ГИС забираем сайт, если API его отдал, и грузим «о нас» с этого URL даже когда зацепка была ОГРН или название. Только после трёх разных точек собираются поля: сначала API выбранной карточки, если поля нет — один GET открытой страницы, иначе «не найдено». Юрлицо: ОГРН/ИНН из зацепки или с карты 2ГИС, затем один GET в ЕГРЮЛ, Федресурс и КАД. Если поиск карт по цифрам ОГРН пуст — имя бренда с карточки РБК (не общий запрос «ногтевой сервис») и повторный поиск 2ГИС, снова со списком на подтверждение. Если ЕГРЮЛ не отдал карточку — один GET [РБК Компании](https://companies.rbc.ru/search/?query=1147746349552) `search/?query={ОГРН}`: ООО — `/id/{ОГРН}-…`, ИП — `/persons/ogrnip/{ОГРНИП}-…`. Берём блок карточки с тем же номером; если в выдаче нет сниппета — открываем саму карточку. Если официальный ЕГРЮЛ и РБК/rusprofile не дали поля — один GET [Checko](https://checko.ru/company/1147746349552): ООО `company/{ОГРН}`, ИП `person/{ИНН}` или `entrepreneur/{ОГРНИП}`. С карточки берём дату регистрации, юридический адрес (если есть), арбитраж, Федресурс и ЕФРСБ. Полка **слабо**. Учредителей и ФИО с Checko не копируем. Прямые GET `kad.arbitr.ru` и `fedresurs.ru` не делаем: боту они недоступны. Нет карточки Checko — HTML-поиск DuckDuckGo **POST** без ключа (`ОГРН site:rusprofile.ru`). JSON `has_captcha` у платного виджета не считаем закрытой страницей. В таблице полка **слабо**, пауза 3 с между запросами DuckDuckGo/rusprofile. Федресурс и КАД с РБК и rusprofile не берём. Несколько организаций — снова список со ссылками, не «не найдено» и не первая запись. Нет ОГРН — юрполя пустые, не «долгов нет». Капчу не обходим. Ключ 2ГИС из `.env` прокидывается и в Docker Compose. Яндекс Places / ППО не используем: это платный API, JS-ключ рейтинг в бэкенд не отдаёт. Ссылка `yandex.ru/maps` как зацепка остаётся типом «карта», карточку с неё через API Яндекса не грузим.

Прогон 2 сентября 2026 (без ключей карт): `https://pinklemon-nails.ru/baumanskaya` отдаёт **404**, живая страница студии — `baumanskaya.html`. ЕГРЮЛ и КАД отдают оболочку с капчей **без ОГРН в HTML** — в таблице это «не найдено», не «есть дела». Федресурс search открывается, но без карточки компании в теле. JSON API карт в этом прогоне не проверялся: в проекте нет `.env` с ключами. Дальше юрполя ЕГРЮЛ ищем через РБК Компании по ОГРН, затем DuckDuckGo → rusprofile, без платного ключа.

Прогон 2 сентября 2026, 19:14 (ключ 2ГИС есть): тот же путь без `.html` — 404, код после этого запрашивает `baumanskaya.html`. У карточек Pink Lemon и «Вишня» 2ГИС не отдал ОГРН, ИНН и сайт — юрполя пустые, это не ноль. Поиск РБК по названию салона не используем: по вывеске приходят десятки чужих юрлиц. Третья зацепка с ОГРН `1147746349552` заполняет ЕГРЮЛ с РБК. ОГРН с сайта берём только если в HTML есть подпись «ОГРН», не любое 13-значное число.

В браузере на карточке 2ГИС сайт виден (Вишня: `vishnyasalon.ru`). Places без доплаты `contact_groups` URL не отдаёт. Бот-GET `2gis.ru/firm/…` даёт 403 через прокси LLM или редирект `/museum`, не ту страницу. Если HTML карточки открылся — забираем `type=website` и «о нас» уже с сайта студии. Если карточка закрыта — DuckDuckGo HTML **без прокси LLM** (иначе пустая выдача), затем проба домена по бренду (`vishnya` → `vishnyasalon.ru`) с проверкой адреса на странице. Зацепка ОГРН: сайт с карточки РБК (блок «Сайт»), `og:description` / `<title>` если нет meta description. На сайте ОГРН/ИНН ищем на главной и по внутренним ссылкам (контакты, политика, реквизиты), только с подписью «ОГРН»/«ИНН». Страницы `2gis.ru` и `duckduckgo.com` не гоняем через `HTTP_PROXY`/`HTTPS_PROXY`.

## Прокси для LLM из РФ

Если модель с вашего компьютера в России не открывается, в `.env` задайте прокси (скопируйте из `.env.example`):

```text
HTTP_PROXY=http://USER:PASSWORD@HOST:PORT
HTTPS_PROXY=http://USER:PASSWORD@HOST:PORT
```

Это **ваш** HTTP-прокси (корпоративный или купленный), в формате `http://логин:пароль@хост:порт`. Публичные «бесплатные» списки не подходят и в репозиторий не пишем. Пустые значения — без прокси. Клиент LLM берёт `HTTP_PROXY` / `HTTPS_PROXY` из окружения. Docker Compose прокидывает их в контейнер; healthcheck на localhost через прокси не идёт.

Вывод модели в отчёте появляется только если заполнены `LLM_*`; иначе строка «вывод модели не найден (нет ключа)». Каждый вызов модели пишется в `data/llm-interactions.log` (ключ маскируется; отключить: `LLM_LOG=0`). Живой прогон: `uv run python scripts/run_llm_probe.py`. Для [Kie Gemini 3 Flash](https://kie.ai/gemini-3-flash) в `.env`: `LLM_BASE_URL=https://api.kie.ai/`, `LLM_MODEL=gemini-3-flash` — клиент сам бьёт `/{модель}/v1/chat/completions`. Ключ Kie (`LLM_API_KEY` или `KIE_API_KEY`). Документация: [docs.kie.ai](https://docs.kie.ai/market/gemini/gemini-3-flash). OpenRouter из РФ часто режется DNS/прокси (502 CONNECT). Клиент пробует прокси, затем прямой канал. `LLM_DIRECT=1` — сначала прямой, потом прокси. Схема прокси `http://`, даже для HTTPS-сайтов.

## Что за рамками

Сознательно не делаем: Instagram и прочие соцсети, Google Карты, фото интерьера, ФССП по людям, платформы с логином, микросервисы, обход капчи, совет купить конкретную точку.

Число мастеров и полный прайс не парсим — блок «масштаб» в индекс не входит. Федресурс, КАД и ЕФРСБ в таблице — с HTML Checko, не с сайтов Федресурса и kad.arbitr.ru. Устойчивость считается по дате и статусу ЕГРЮЛ/ЕГРИП. Ленту отзывов 2ГИС (даты, 90 дней, плюс/минус) не показываем и не кладём в индекс: API отдаёт только рейтинг и счётчик, страница карт закрыта. Расход токенов и стоимость берём из ответа модели (`usage.total_tokens`, `usage.cost` у OpenRouter). Свои тарифы в `.env` (`LLM_USD_PER_1M_PROMPT` / `LLM_USD_PER_1M_COMPLETION`, доллар за миллион токенов) нужны, если провайдер `usage.cost` не прислал. Можно писать `0.15` или `0,15`.
